# Using the project workspace

Start at `/dashboard`. Choose your role, then follow a project through four stages:

1. **Submit — NGO.** Enter the project details, location, evidence and starting environmental measurements. Submission saves a project; it does not issue tokens.
2. **Check & review — NGO or validator, then validator.** Open the project and run its checks. Read the findings and supporting evidence in the same page. If changes are requested, the project owner updates and resubmits it.
3. **Issue tokens — validator, then system.** After reviewing the evidence, choose **Approve & issue tokens**. The backend uses its configured owner key and Sepolia test ETH. No owner wallet signature or separate governance-page vote is required. The transaction remains pending until confirmed. Failures and legacy records without receipts require attention rather than being shown as complete.
4. **Complete — everyone.** View the confirmed transaction and recipient in the project page, or open **Issued tokens** for the registry. Test tokens have no monetary value.

Every project shows **What happens next** and **Who acts**. The workspace shows in-progress and completed projects using the same rules. A transaction hash, approved status, or marketplace listing alone does not mean issuance succeeded.

The **More tools & demos** menu contains maps, analytics, browser-local voting and simulated marketplace features. None is an extra required step in completing a project. Organisation verification and profile pages remain available there when needed. Existing listing tools are at `/demo/project-listings`.

The underlying data checks and validator login remain required. This is a demo review workflow, not a claim of decentralized consensus or certified carbon-credit issuance. Restart the backend after updates and sign in again as a validator to get a fresh session.
